# AiBet Money — сайт с админкой Pages CMS

Ежедневная работа: зайти в админку → создать или открыть разбор → написать текст, загрузить обложку → сохранить.
GitHub остаётся хранилищем сайта, но вручную менять файлы для обычных публикаций больше не нужно.

## Главная страница — новая композиция

- Первый экран: короткий заголовок и два входа в футбол и хоккей.
- Логотип: готовая горизонтальная сборка из предоставленной дизайн-системы. Геометрия знака и надпись не пересобираются средствами CSS. Исходные изображения находятся в assets/brand.
- Крупный блок разборов появляется при наличии опубликованных статей. В материале можно включить «Главный разбор на главной». Если отмечено несколько, выбирается самый новый; без отметок — последний опубликованный.
- Ниже главного материала показываются до шести остальных разборов. Фильтр «Все / Футбол / Хоккей» работает по всем отображаемым карточкам.
- «Итоги разборов» показывает до пяти материалов с результатом «Плюс», «Минус» или «Возврат». Незавершённые материалы туда не попадают.
- Блок калькулятора появляется, когда в настройках заполнена ссылка на существующий инструмент.
- В «Настройках сайта» редактируются заголовок, вводный текст, три блока метода и тексты блока Telegram.
- При пустой коллекции лента и итоги скрыты. На главной остаются навигация по видам спорта, метод и ссылка на канал. Вымышленные матчи и показатели не добавляются.
- Без JavaScript доступны материалы, ссылки и навигация; JavaScript добавляет компактное мобильное меню и фильтр.

Обложки карточек обрезаются по центру до формата 16:9. Авторизация Pages CMS и публикация в GitHub требуют отдельно настроенного доступа, как описано ниже.

## Один раз включить сайт

Если сайт ещё не размещён:

1. Распакуй архив.
2. Создай Public-репозиторий GitHub и загрузи туда содержимое папки AIBET_WITH_ADMIN.
3. В корне репозитория должны быть `index.html`, `_config.yml`, **.pages.yml**, папки `_layouts`, `_includes`, `_data`, `_analyses`, `assets`.
4. Settings → Pages → Deploy from a branch → main → /(root) → Save.
5. Дождись успешной сборки.

Если старая версия уже работает, загрузи новые файлы поверх неё. Существующие статьи в `_analyses` не удаляй. Не меняй имя репозитория или домен.
Если браузер не перенёс `.pages.yml` вместе с остальными файлами, загрузи его отдельно через Add file → Upload files. Он должен лежать рядом с `_config.yml`.

## Один раз подключить админку

1. Открой https://app.pagescms.org .
2. Нажми вход через GitHub и войди в свой аккаунт.
3. Подключи GitHub App Pages CMS к аккаунту, которому принадлежит сайт.
4. На экране выбора репозиториев выбери **Only select repositories** и укажи только репозиторий этого сайта.
5. Подтверди запрошенные права. Для публикации сервису нужен доступ к чтению и изменению файлов этого репозитория.
6. В Pages CMS выбери репозиторий и ветку **main**.
7. Pages CMS прочитает готовую `.pages.yml`. Должны появиться разделы «Разборы матчей», «Настройки сайта», «О проекте», «Методология», «Контакты» и работа с медиа.

Если вместо этих разделов сервис предлагает создать конфигурацию, проверь наличие `.pages.yml` в корне выбранного репозитория и выбранную ветку.
На сайте есть ссылка «Админка», которая ведёт к входу в Pages CMS. Сам интерфейс управления обслуживает Pages CMS, а не GitHub Pages.

## Что можно делать в админке

- Создавать, редактировать и удалять разборы.
- Писать текст в визуальном редакторе с заголовками, списками и ссылками.
- Загружать обложки и изображения через медиаменеджер.
- Менять команды, турнир, коэффициенты, аргументы и таблицу статистики.
- Выбирать главный разбор для первого экрана.
- Добавлять счёт, результат выбора и послематчевый комментарий.
- Заполнять SEO-заголовок и описание.
- Менять главный заголовок, вводный текст, блоки о подходе, блок Telegram, ссылки, калькулятор и подвал.
- Редактировать текст страниц «О проекте», «Методология», «Контакты».

Свободно перестраивать верстку, менять программную логику или подключать платежи эта админка не предназначена. Это управление контентом и предусмотренными настройками.

## Публикация

1. В разделе разборов создай материал.
2. Укажи адрес латиницей и дефисами, например `lille-lens-2026-11-01`.
3. Выбери дату и **московское время** матча. Сайт собирается с Europe/Moscow.
4. Заполни заголовок, вступление, текст, обложку и нужные показатели.
5. Включи «Показывать на сайте» и сохрани материал в CMS.
6. CMS сама сохранит изменения в GitHub. После успешной пересборки GitHub Pages они появятся на сайте.

В интерфейсе сервиса кнопка сохранения может называться Save. Включение поля «Показывать на сайте» определяет публикацию страницы.
После правки не требуется вручную скачивать .md или открывать редактор файлов GitHub.

Первую дату публикации при дальнейших правках оставляй исходной. Дату обновления меняй при существенных правках.
Для счёта заполняй оба поля. Пока игра не завершена, оба оставь пустыми.

## Снятие с публикации и черновики

Выключение «Показывать на сайте» снимает страницу с публикации при следующей сборке. Материал пропадает из списков, sitemap и llms.txt.
**Это не приватное хранилище:** в публичном репозитории исходный файл и загруженные изображения доступны через GitHub. Личные данные, закрытые прогнозы и пароли здесь не храни.
Существующие статьи предыдущей версии без поля `published` продолжают считаться опубликованными.
Pages CMS не превращает сайт в закрытую ВИПку и не проверяет оплату подписки.

## Доступ и безопасность

Вход в админку — через GitHub. Включи 2FA в GitHub и сохрани коды восстановления.
Не передавай пароль GitHub и не публикуй токены. Этот архив их не содержит и не требует вставлять их в файлы сайта.
Pages CMS — внешний сервис с доступом к содержимому выбранного репозитория. Разрешай доступ только к нужному сайту; отключить приложение можно в настройках GitHub.
Шаблоны сайта и конфигурация CMS открыты, но само их чтение не даёт прав редактировать репозиторий.

## Проверка после подключения

Сначала создай учебный материал без личных данных, добавь картинку, включи публикацию и сохрани.
Проверь страницу статьи, раздел спорта и обложку. Затем выключи публикацию и убедись, что страница снята после новой сборки.
Если публикация не обновляется, открой Actions в GitHub и проверь результат Pages build and deployment.

Официальная инструкция сервиса: https://pagescms.org/docs/quick-start/
